# KV002: hardcoded credential

Severity: always an error.

## What it catches

A credential written into source, a notebook or a config file. kv-cli reports
a literal when either of these rules matches.

1. Its shape. A value pattern matches it under any name and anywhere in the
   file, including comments, notebook outputs and split strings such as
   `"ghp_abc" "def"`. The shapes cover AWS keys, GitHub, Slack, OpenAI,
   Anthropic, Stripe and Google keys, JWTs, PEM private keys and URLs with a
   password.
2. Its name. It is assigned to, or compared with, a name that matches
   `secrets.key_patterns`, such as `*password*`, `*token*` or `*api_key*`.

```python
DB_PASSWORD = "s3cr3t-value-1234"         # KV002: name rule
if password == "s3cr3t-value-1234":       # KV002: comparison
```

The output redacts the value, shown as `value "s3…" (<redacted>, 17 chars)`,
so the CI log doesn't leak the credential.

## What it ignores

These exceptions apply to the name rule only. A literal that matches a shape
is always reported.

- Names that refer to a credential without holding one: `secret_name`,
  `token_url`, `credentials_path` (`secrets.exempt_key_patterns`).
- Placeholders such as `changeme`, `your-api-key-here` and `<token>`
  (`allow_values`, `placeholder_patterns`).
- References such as `${VAR}`, `{{ env_var('X') }}` and f-string
  substitutions. A template is judged by what it writes down, so a
  hardcoded fallback is still reported: `{{ env_var('X', 's3cr3t') }}`,
  `{{ 's3cr3t' }}`, or a `{% if %}` branch that is a literal.
- Values shorter than `min_value_length`.

Names are matched as written and in snake_case, so `privateKey` matches
`*private_key*`.

## How to fix it

Read the value from the environment or a secret store:

```python
import os
DB_PASSWORD = os.environ["DB_PASSWORD"]
```

`kv-cli fix` makes this rewrite and adds `import os` if it is missing. A
hardcoded default in a function signature is left as a `manual:` item,
because `os.environ[...]` in a default is read once, at import time.

Afterwards, rotate the credential. A value that was ever committed is still
in git history, whatever the file says now.

## How to suppress one line

```python
legacy_token = "abcd1234efgh"  # kovallent:allow-secret
```

The marker counts only inside a comment. JSON has no comments, so exclude a
fixture file with `scan.exclude` instead.

## Contract keys

`secrets.key_patterns`, `secrets.value_patterns`,
`secrets.exempt_key_patterns`, `secrets.allow_values`,
`secrets.placeholder_patterns`, `secrets.min_value_length`,
`secrets.ignore_marker`, `fix.externalize_secrets`, `fix.env_var_prefix`
