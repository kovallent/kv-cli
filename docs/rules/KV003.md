# KV003: pinned infrastructure identifier

Severity: a warning by default, so turning it on doesn't break CI on day one.
Set `infrastructure.severity: error` to gate on it, or run `audit --strict`.

## What it catches

An identifier that ties code to one environment, such as a warehouse,
catalog, bucket, cluster ID, workspace URL, broker or JDBC endpoint. The
code works in that one environment and either breaks in the others or,
worse, writes to the wrong one.

```python
WAREHOUSE = "ANALYTICS_PROD_WH"           # KV003: name rule
df.write.parquet("s3://acme-prod-orders/") # KV003: object-store URI
```

Python files only. Config files are where environment-specific values
belong, so KV003 never applies to them.

Framework profiles add their own identifiers in files that use the
framework. For example, Snowpark adds `account` and `role`, and Airflow adds
`conn_id`, `pool` and `queue`. `kv-cli frameworks` lists them all.

## How to fix it

Derive the value from the target environment:

```python
WAREHOUSES = {"dev": "ANALYTICS_DEV_WH", "prod": "ANALYTICS_PROD_WH"}

def run_report(target_environment: str = "dev"):
    warehouse = WAREHOUSES[target_environment]
```

`kv-cli fix` never rewrites these, because the right replacement is a
deployment decision.

## What it ignores

- Values in `infrastructure.allow_values`, such as `local`, `dev` or `test`.
- Names in `infrastructure.exempt_key_patterns`, such as `*_column` or
  `*_type`.
- Values shorter than `min_value_length`.
- Comparisons such as `if catalog == "prod"`. Those branch on an environment
  rather than pin one.

## How to suppress one line

```python
LEGACY_BUCKET = "s3://acme-archive/"  # kovallent:allow-infra
```

## Contract keys

`infrastructure.enabled`, `infrastructure.severity`,
`infrastructure.key_patterns`, `infrastructure.value_patterns`,
`infrastructure.allow_values`, `infrastructure.exempt_key_patterns`,
`infrastructure.ignore_marker`
