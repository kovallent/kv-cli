# KV004: naming convention

Severity: `naming.severity`, a warning by default, so adding a rule doesn't
break CI on day one. Run `audit --strict` to gate on it, or set
`naming.severity: error`.

## What it catches

A Python function whose name doesn't match a naming rule in the contract.
There are no rules by default, so KV004 reports nothing until a contract adds
one.

```yaml
naming:
  severity: warning
  rules:
    - name: pipeline_functions
      applies_to: in_scope
      pattern: "^[a-z][a-z0-9_]*$"
      message: "pipeline entrypoints use snake_case"
```

```python
@task
def LoadOrders(target_environment: str = "dev", dry_run: bool = False):  # KV004
    ...
```

```text
    14  warning  KV004  `LoadOrders` does not match naming rule `pipeline_functions`
        name must match `^[a-z][a-z0-9_]*$`: pipeline entrypoints use snake_case
```

`pattern` is a regex matched against the whole function name, as if it were
wrapped in `^(?:...)$`. It must compile, and it must not match the empty
string: a pattern that accepts an empty name requires nothing of a name.
`kv-cli contract check` reports either problem with its line.

The finding's `symbol` is the function name and its `subject` is the rule's
`name`, so the fingerprint follows the same formula as every other finding
and leaves out the line number.

## Which functions are checked

- `applies_to: in_scope`, the default, checks the functions the scope line
  counts as in scope or framework-exempt. **Framework-exempt functions are
  checked too.** A framework owns a function's signature, not its name, so a
  dbt `def model(dbt, session)` still has a name worth checking.
- `applies_to: all_functions` checks every function definition.

Either way, a name that matches `applies_to.exempt_name_patterns` (`_*` and
`test_*` by default) is never checked, so `_private` helpers and tests are
left alone.

KV004 applies under every framework profile, because every one of them has
Python function names. It checks Python files only.

## What it does not count toward

KV004 never counts toward a compliance rate. That rate is about the parameter
contract, KV001, and a naming finding doesn't change any count in the scope
block. `report_only` is a KV001 field, so it is absent on KV004 findings.

## How to fix it

Rename the function, and every caller with it.

`kv-cli fix` never renames a function, because a rename breaks every caller
it can't see: other repositories, scheduler configs, dbt's own call to
`model`. It lists each KV004 finding as a `manual:` item instead.

## How to turn it off for a function

There is no per-line marker for KV004. Exempt the function by name, which also
takes it out of KV001:

```yaml
applies_to:
  exempt_name_patterns: ["_*", "test_*", "legacy_*"]
```

Or narrow the rule: `applies_to: in_scope` leaves out functions the contract
doesn't govern.

## Contract keys

`naming.severity`, `naming.rules[].name`, `naming.rules[].applies_to`,
`naming.rules[].pattern`, `naming.rules[].message`,
`applies_to.exempt_name_patterns`
